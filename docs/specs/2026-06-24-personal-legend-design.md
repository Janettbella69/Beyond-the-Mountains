# 寻找天命（Personal Legend）— 设计文档

> 工作代号 `personal-legend`（随时可改）。本文是**设计 spec**，不是实现计划；实现计划由后续 writing-plans 产出。

- **状态**：设计定稿，待 review
- **日期**：2026-06-24
- **一句话定位（logline）**：一个 **AI 驱动的互动叙事游戏**——少年踏上寻找天命的旅程，沿途遇见的人与故事由 AI 实时生成、每局不同，但始终被一条手写的命运主线和母题牢牢牵引；终点是一面镜子，照见你一路选择活成的样子。

---

## 1. 愿景与定位

借《牧羊少年奇幻之旅》的**精神母题**（天命 / 预兆 / 世界之魂 / Maktub），做一个**全新世界、全新主角**的"寻找天命"之旅。不是冒险动作大作，而是一部**借少年旅程叩问人生根本命题**的互动叙事作品。

**差异化与惊艳点**：不在画面维度，在 **AI 叙事维度**——"每个人都长出一条不一样的、活的天命故事"。这是当下最前沿、也最契合作者（AI builder / 技术 PM，护城河 = eval 体系 + 数据闭环）独门优势的方向。

**第一步目标**：一个**可玩、可参赛的垂直切片**（vertical slice），用来验证"AI 生成相遇 + 手写主线母题"这套灵魂能否成立。不是 3A，不是纯设计文档。

---

## 2. 核心姿态（已定，不再动摇）

- **借灵魂、不借躯壳**：只取公有领域的思想 / 母题，不碰原著的具体表达。版权干净（详见 §7 红线）。
- **"C 骨架 + B 灵魂"**：系统可生成的自由（C：每局不同、可复玩）+ 手写主线的故事性（B：有弧光、能打动人）。
- **AI 是命门，不是装饰**：核心玩法引擎，而非加分项。
- **少即是深**：垂直切片宁可窄而深（4 支柱做透），不要宽而浅。

---

## 3. 叙事架构：糖葫芦 / 串珠结构

一根**手写主线签子**串上若干**AI 生成的相遇珠子**。签子保证弧光与故事性，珠子保证丰富与可复玩；每颗珠子都挂在签子的某个节点上、受母题约束，所以"活而不乱"。

### 3.1 情节弧光（纵轴 · 手写 · 确定性）

经典英雄之旅骨架，固定且必经：

```
召唤·出发 → 试炼·求道 → 绿洲·相遇 → 至暗·考验 → 顿悟 → 回归（宝藏在自身）
```

这层是写死的状态机，保证每一局都有完整的情感弧光、不跑偏。

### 3.2 主题命题（横轴 · 母题库）

**主轴命题（贯穿全程，不占单独相遇，所有命题最终汇入它）**：
- **意义 / 自我（天命）**：我是谁、我的天命是什么、宝藏为何在自身。

**4 根支柱命题（各挂一类相遇，彼此成张力）**：
1. **恐惧 / 勇气**：敢不敢出发、敢不敢面对失败。
2. **志业 / 热爱**：世俗的成功 vs 内心的召唤；你真正被召唤去做的那件事。
3. **爱 / 羁绊**：最锋利的两难——爱 vs 天命，成全还是占有。
4. **信念 / 诱惑**：坚持初心，还是被安逸、捷径、金钱收编。

**被降级的命题**（出现在相遇里，但不设为核心支柱，以免冲淡"孤独旅人找天命"的主调、撑散切片）：友情（并入"羁绊"）、生死 / 无常（可做"至暗"的一记高潮）、家庭 / 根（"出发"与"回归"的背景）。

### 3.3 命题轴 × 情节轴的咬合

二者不是平行，而是天然合成一条线（这正是英雄之旅的内在骨架）：

| 情节阶段 | 主导命题 |
|---|---|
| 召唤·出发 | 恐惧 / 勇气 |
| 试炼·求道 | 志业 / 热爱 |
| 绿洲·相遇 | 爱 / 羁绊（最甜的诱惑） |
| 至暗·考验 | 信念 / 诱惑（坚持还是放弃） |
| 顿悟 → 回归 | 汇入 **意义 / 自我** |

### 3.4 相遇系统（珠子）

- 每个相遇 = **一类人 + 一道人生命题 + 一段两难 + 一句领悟**。
- 由 AI 实时生成，输入：当前主线节点（母题约束）+ 玩家状态（人设 / 信念 / 历史选择 / 遇过的人）+ 世界观 bible。
- 输出为**结构化数据**（schema，见 §5），而非自由文本，便于校验与驱动游戏逻辑。
- 每个支柱配**手写锚点相遇**打底（保证质量与母题不偏），AI 负责在其间填充、变奏、个性化。

### 3.5 "深刻不喊口号"的四个抓手

1. **每个相遇沉淀一句"领悟"**：玩家拿到的不是道具，是一个对人生的洞察 / 一次价值观的塑形。
2. **选择即价值观**：抉择没有对错输赢，只问"你是谁、你信什么"，累积成少年的人生观并改写结局。
3. **两难、不给标准答案**：事业 vs 爱情、坚持 vs 放下、天命 vs 责任——呈现张力，让玩家自己权衡。
4. **结局是面镜子**（见 §3.6）。

### 3.6 镜子结局（压轴 · 题眼）

整个作品的题眼：把"选择即价值观"与"宝藏在自身"两大母题在最后一刻**合二为一**。前面所有选择，不为通关，只为在这一刻照见你自己。

落地两笔，确保"照得出人、而非一句漂亮话"：

1. **结局由真实选择"长"出来，而非预设分支**：全程记录玩家在 4 支柱上的选择（恐惧时进/退、志业选世俗成功/内心召唤、爱与天命如何取舍、至暗时坚持/妥协），终点由 AI 把这些选择 + 遇过的人 + 沉淀的领悟，写成一段**独一无二、第二人称的「你的天命之书」**——每个玩家结局文本都不同。这是实时叙事引擎最催泪的用法，兑现"每个人走出不一样的天命"。
2. **首尾同一场景**：结局回到"召唤"的那个起点画面，但你的眼睛已经不同。同一片风景，开局与结局读到的意义完全相反——宝藏一直在出发的地方，只是当初的你看不见。**用同一个场景，照出你的蜕变。**

## 4. 玩法与呈现

- **玩法形态**：偏叙事 + 轻系统。互动叙事 / 视觉小说为主体（读 + 选择），辅以一个"**信念 / 预兆**"的轻机制（玩家的信念作为一种可累积、可消耗、影响相遇与结局的资源）。
- **呈现**：
  - **文字实时生成**（灵魂层）：天命、相遇、对话由 LLM 运行时生成。
  - **2D 资产库**（皮）：立绘 / 场景 / 道具由**开发期** AI 批量生成 + 人工定稿（借此解决角色一致性），运行时按标签调用 / 组合，**不**运行时现画。
  - **TTS 配音**（可选加分）：把生成的文字实时读出来，带情感与音色。
  - UI：视觉小说式（文字 + 立绘 + 背景 + 选项）。
- **不做**：3D、实时生成 3D / 动画 / 视频（技术不成熟且与"无限相遇"根本冲突）、重动作战斗。

---

## 5. 技术架构：受控的 Dynamic Workflow

核心原则：**dynamic 负责"活与无限"，static 负责"弧光与不跑偏"，eval 校验负责"质量与母题不崩"**。三者缺一，游戏要么死板、要么发散、要么廉价。

```
┌─────────────────────────────────────────────────────┐
│  编排层 (Orchestration)                              │
│   静态主线状态机  ──drives──▶  动态相遇生成器(LLM)    │
│   (确定性 workflow)            (dynamic workflow)     │
└───────────────┬─────────────────────┬───────────────┘
                │                     │
        ┌───────▼────────┐    ┌───────▼────────┐
        │ 约束/校验层     │    │ 状态/记忆层     │
        │ schema + 母题   │    │ 玩家档案/世界   │
        │ LLM-judge 守门  │    │ 状态/伏笔呼应   │
        └────────────────┘    └────────────────┘
                │
        ┌───────▼────────┐    ┌────────────────┐
        │ 资产层(预生成)  │    │ 表现层(VN 前端) │
        │ 2D 库 + TTS     │    │ 文字+立绘+选项   │
        └────────────────┘    └────────────────┘
```

- **① 编排层**：静态状态机驱动主线（保证必经节点与弧光）；动态相遇生成器只在节点的"格子"里调 LLM 生成内容，不放飞。
- **② 约束 / 校验层**：相遇用 **schema** 约束输出（字段：角色、情境、所叩问的命题、选项、后果、对玩家状态的影响、领悟）；生成后过一道 **LLM-judge**，判定是否符合母题 / 世界观 / 一致性，不合格则重生成或回退。**这是质量命门，正对作者的 eval 护城河。**
- **③ 状态 / 记忆层**：玩家档案（人设 / 信念值 / 历史选择 / 遇过的人）+ 世界状态 + 伏笔；记忆检索让后续相遇能呼应前文、回收伏笔——**这是"故事性强"的技术来源**。
- **④ 资产层**：开发期预生成的 2D 库 + 运行时 TTS。
- **⑤ 表现层**：Web 视觉小说式 UI。

**选型（推荐，待实现阶段最终确认）**：
- 编排：**Mastra**（TS 生态，自带 workflow + agent + memory 原语，前后端一条龙；作者已有 Agno→Mastra 经验）。备选 LangGraph（状态机更原生）。
- 前端：**Web · React / TS**（与 Mastra 同生态，最快出 demo）。
- LLM / 图像模型 / TTS 具体厂商：实现阶段定。

## 7. 版权红线（实现时必须遵守）

**✅ 可自由用（公有领域的思想 / 母题 / 原型）**：追寻天命、自我实现的主题；预兆、世界之魂、Maktub、"真心渴望时宇宙会相助"等母题；导师 / 试炼者 / 爱人 / 骗子 / 国王等原型功能；"为远方宝藏出发、终发现宝藏在出发地 / 在自身"这一古老骨架（源自《一千零一夜》"两个做梦人"，博尔赫斯亦复述，属公有领域）；朝圣 / 旅程结构。

**❌ 不能碰（受保护的具体表达）**：原著角色专名（Santiago / Fatima / Melchizedek 等）及其设定；原著那条具体情节链（西班牙牧羊→水晶店→撒哈拉商队→绿洲→金字塔→无花果树下）；原著台词 / 箴言原文；"牧羊少年奇幻之旅 / The Alchemist"作游戏名；宣传"改编自柯艾略"。

**对外口径**：灵感源自"寻找天命"的古老寓言传统。

> 提示：真要商业化 / 参赛，临门让懂版权的人再过一眼是稳妥做法；但方向上本设计是干净的。

## 8. 关键风险与对策

| 风险 | 对策 |
|---|---|
| 程序化叙事退化为"无意义随机拼贴"、空洞 | 静态主线骨架 + 母题约束 + 手写锚点相遇 + LLM-judge 校验 |
| AI 跑偏 / 出戏 / 胡说 | schema 结构化输出 + 母题/一致性校验 + 重生成/回退 |
| 角色 / 画风一致性飘 | 视觉资产走开发期预生成 + 定稿（可训角色 LoRA），不运行时现画 |
| 相遇像散沙、无呼应 | 记忆层 + 伏笔检索，让后文呼应前文 |
| "深刻"沦为口号 | §3.5 四抓手 + §3.6 镜子结局 |
| 实时 LLM 成本 / 延迟 | 部分相遇可"开发期预生成池 + 运行时动态挑选组合"，混合降本 |
