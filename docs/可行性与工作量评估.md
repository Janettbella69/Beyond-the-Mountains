# 可行性与工作量评估 — Personal Legend

> 配套设计 spec：`docs/specs/2026-06-24-personal-legend-design.md`
> 日期：2026-06-24｜状态：初评（待按"单干/组队、前端底子、目标档位"三项收窄）

本文不灌鸡汤，按实话估。

---

## 1. 核心判断

**"能不能跑通"和"能不能惊艳"，是两个不同的问题。**

- **技术核心恰好是作者的优势区**：编排（Mastra workflow）、schema 约束、LLM-judge 校验、Agent 记忆——全是做导购 Agent（Agno→Mastra）的老本行。所以"搭出一个能端到端跑的最小闭环"不难，甚至比预想快。
- **要达到 spec 立的调**（深刻 / 故事性强 / 镜子结局），**瓶颈不在技术，在内容、美术、AI 叙事调优**——这三块技术能力加速不了，也不是作者最强的区。**这是真正的硬骨头，也是最容易被低估的地方。**

---

## 2. 模块工作量拆解（难度 = 对作者而言）

| 模块 | 难度 | 说明 |
|---|---|---|
| 编排层（状态机 + 动态生成器） | ★☆☆ | 主场，Mastra 直接上 |
| 校验层（schema + LLM-judge） | ★☆☆ | eval 护城河，差异化优势 |
| 记忆 / 状态层 | ★★☆ | Mastra 有原语，中等 |
| **AI 叙事调优**（让相遇活而不空） | ★★★ | 核心风险，靠反复迭代；有 eval 优势但仍耗时 |
| 前端 VN UI（React/TS） | ★★☆ | VN UI 本身不复杂 + AI 辅助；看前端底子 |
| **美术资产**（2D 一致性） | ★★★ | 易低估：AI 生成图 ≠ 免费，调一致性 + 筛选定稿是真工作量 |
| **内容创作**（主线 + 锚点 + 世界观，要"深刻"） | ★★★ | 最硬，纯创作功力，技术加速不了 |

**一句话**：三颗 ★★★ 里，只有"AI 叙事调优"能靠作者的技术 / eval 优势扛；"内容创作"和"美术"是另一种能力，决定 demo 是惊艳还是半成品。

---

## 3. 时间量级感

> ⚠️ 不是承诺，变量很大——取决于单干还是组队、质量目标、投入强度。仅给"量级感"。

- **能跑通的最小闭环**（一条最短弧光 + 一次 AI 相遇 + 校验 + 极简 UI）：技术主场 + AI 辅助，**~1–2 周**量级。
- **像样、能参赛的垂直切片**（若干锚点内容 + 基础美术 + 调优到不崩不空）：**~1–2 个月**量级——且这俩月主要耗在**内容 / 美术 / 调优**，不是技术骨架。

---

## 4. 降风险策略（把"能不能做出来"从悬念变确定）

1. **切片砍到最小**：先用"2 支柱最小版"，甚至"1 条最短弧光 + 1 个锚点相遇"打通端到端，验证灵魂，再扩。别一上来全做。
2. **美术先躲坑**：第一版干脆**纯文字 + 氛围背景，不做立绘**（反正灵魂在文字），或用极简统一风格（剪影 / 单色）规避一致性难题。把力气全押叙事。
3. **扬长**：作者专注技术骨架 + AI 调优（最强区），内容写作和美术若有队友 / 外援分担，把握度直接拉满。

---

## 5. 诚实结论

- 单做一个**"跑通灵魂"的 demo —— 能，而且很适合作者**（技术核心正中优势）。
- 独自全包一个**"精致惊艳的完整体验" —— 偏重**，主要被**内容和美术**拖，不是技术。
